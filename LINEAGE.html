Feature Lineage Reference

Maps how features and mechanics are interlinked. Goal: understand ripple effects of changing any one thing without re-exploring the codebase from scratch. Update this document at the end of every session when new features or data model changes are introduced.

S: The State Object

S is the single source of truth. No component holds its own state. Every mutation writes to it; every display reads from it.

let S = {
  // Script metadata
  title:            string,
  author:           string,
  productionNotes:  string,    // Outline → Production Details; split-pane markdown editor; no pushUndo (Session 18)
  copyrightText:    string,    // Outline → Production Details; auto-grows; no pushUndo (Session 18)

  // Master character list
  characters: [{ name, description, archived }],

  // Content tree
  acts: [{
    name, description,
    notes: [],                 // Session 16
    scenes: [{
      name, description,
      setting:     string,     // promoted from line type (Session 13)
      lockedNum:   string,     // overrides sceneLabel() when set (Session 10)
      colorLabel:  string,     // outline card color (Session 15/17)
      status:      string,     // Outline/Draft/Revised/Final (Session 15)
      notes: [],               // Session 16
      lines: [{
        type:           'direction'|'dialogue'|'action'|'bookmark',
        value:          string,
        characters:     [{name,description}],  // dialogue only; max 2 (Session 17)
        dialogueAction: string,                // dialogue parenthetical
        cues:           {enters:[], exits:[]}, // direction only — string arrays
        label:          string,                // bookmark only
        notes:          [],                    // any type (Session 16)
        colorLabel:     string
      }]
    }]
  }],

  revisions:    [{name, colorIdx, timestamp, snapshot}], // Session 9
  scenesLocked: boolean,     // Session 10
  colorLabels:  {}           // label names for color dots (Session 17)
};

Render Pipeline

Standard mutation sequence

pushUndo()→ modify S→ autoSave()→ render()

autoSave() expands to

lsSaveScript()+ writeToFileHandle()+ updateSaveIndicator()+ computeRevisionChanges()

What render() calls

  • renderScene(ai, si) for each visible scene
  • updateDirCues() — only when the direction/cue pill is active
  • updateUndoRedoBtns(), updateSaveIndicator()
  • renderRPNotes(), renderRPBookmarks()
  • renderStats() — only when the stats panel is open

What render() does NOT call — triggered by switchTab() instead

  • renderView() — View tab (computed on demand)
  • renderOutline() — Outline tab; includes renderProductionDetailsSection() at the bottom (Production Notes + Copyright textareas)
Decision rule: If new state must stay live during editing, put its render call inside render(). If it's computed on demand when the user opens a specific tab, put it in switchTab().

Character Registry — Mutation Chains

S.characters[] is the authoritative registry. Lines store copies of name + description, not references. Mutations to the registry must manually propagate to all lines.

Character CREATED

→ S.characters.push({name, description, archived:false})
→ autoSave() → render()
→ direction cue chips refresh (updateDirCues() if pill is active)
→ character dropdown in input bar regenerates on next render

Character RENAMED — saveCharEdit()

pushUndo()

S.characters[i].name = newName;
S.characters[i].description = newDesc;

// Propagate to all dialogue lines
S.acts.forEach(a => a.scenes.forEach(sc => sc.lines.forEach(l => {
  if (l.characters) l.characters.forEach(c => {
    if (c.name === oldName) { c.name = newName; c.description = newDesc; }
  });
})));

// Propagate to direction cue arrays (string copies, not references!)
S.acts.forEach(a => a.scenes.forEach(sc => sc.lines.forEach(l => {
  if (l.type === 'direction' && l.cues) {
    l.cues.enters = l.cues.enters.map(n => n === oldName ? newName : n);
    l.cues.exits  = l.cues.exits.map(n  => n === oldName ? newName : n);
  }
})));

autoSave() → render()
Trap: Character names in cues.enters[] and cues.exits[] are string copies. A rename must update both S.characters[] AND all cue arrays. Missing the cue update leaves stale names in direction lines.

Character ARCHIVED

charHasUsage(name) check — blocks if any lines reference this character

→ S.characters[i].archived = true
→ Disappears from input bar autocomplete and direction cue chips
→ Existing lines REMAIN — archived chars stay in all dialogue lines
→ pushUndo() → autoSave() → render()

Character DELETED

removeCharUsage(name):  // called first
  for each dialogue line:
    if characters.length === 1 → remove entire line
    if characters.length === 2 → filter from array, keep line
  for each direction line:
    l.cues.enters = l.cues.enters.filter(n => n !== name);
    l.cues.exits  = l.cues.exits.filter(n  => n !== name);

S.characters.splice(idx, 1)
pushUndo() → autoSave() → render()

Direction Cues — Second Character Registry

Direction lines track character names independently as string arrays in cues.enters[] and cues.exits[]. This is a parallel registry — not references to S.characters[].

FunctionWhat it does
getSceneCharsAt(scene, lineIdx)Replays all enters/exits up to lineIdx to compute who is currently on stage. O(n) per call.
validateMoveLine(scene, fromIdx, toIdx)Uses getSceneCharsAt to block drags that create invalid cue sequences.
updateDirCues()Refreshes chip UI when the direction pill is active. Called by render() when cue input is open. Grays out chips for chars already on/off stage.
Invariant: A character cannot enter if already on stage; cannot exit if not on stage. Any feature that moves dialogue lines must respect this — use validateMoveLine().

Undo / Redo Contract

pushUndo() mechanics

1. JSON snapshot of S via stateJSON()
2. Splice future states from undoStack (if undoCursor < length-1)
3. Push snapshot; cap at 50 entries
4. If stack hits 51: shift() oldest entry; set undoCursor = length-2
5. Update undoCursor

doUndo() / doRedo()

→ Restore S from snapshot at new cursor position
→ Restore S.revisions unconditionally: p.revisions || []
→ render()
→ computeRevisionChanges()

Stack reset — these 6 paths wipe undo history

  • loadFromData() — opening a file
  • resumeFromLS() — restore from browser storage
  • loadSample() — demo script
  • doNewScript() — new script
  • parseFountain() — Fountain import
  • parseFDX() — FDX import

Does NOT call pushUndo() — cannot be undone

  • updateProductionNotes(), updateCopyrightText()
  • Title and author edits from the title bar
  • All Settings changes (font, colors, hotkeys, etc.)
Rule: Any new mutation that changes S.acts content MUST call pushUndo() first. Forgetting means the change cannot be undone.

File System Access API + IndexedDB

When a user links a disk file, fileHandle is stored in IndexedDB via fhIdbSet() and restored on load via fhIdbGet(). autoSave() calls writeToFileHandle() to overwrite. doNewScript() resets via setFileHandle(null) to prevent overwriting the old file with empty data.

Find & Replace — Intentional Isolation

Find & replace is deliberately isolated from character data. This is by design.

SearchesNever searches
l.value (main text body)Character names (l.characters[*].name)
l.dialogueAction (parenthetical)Scene settings (scene.setting)
Act/scene names and descriptions
Bookmark labels
Implication: Renaming a character via Find & Replace is impossible by design. Renames must go through saveCharEdit(), which propagates to all dialogue lines AND direction cue arrays.

To make a new line type searchable: add a filter chip in find bar HTML, add an entry to findFilters, add a case in buildFindMatches(), and add cases in doReplace() + doReplaceAll().

Deployment Contract

After any change to script_maker.html, before pushing to GitHub:

  • 1.Run ./sync.sh — regenerates docs/index.html with docs/ paths rewritten to site-relative
  • 2.Bump CACHE_NAME in docs/sw.js to scriptwriter-v1.XX — forces PWA cache invalidation
  • 3.Bump version string in HTML (setup-version div + Settings panel description)
  • 4.Commit and push → GitHub Pages auto-deploys from docs/
  • 5.Update LINEAGE.html if any data model, load path, or fanout relationships changed
Never edit docs/index.html directly. It is overwritten by sync.sh on the next run.
